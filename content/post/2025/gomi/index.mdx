昔、ターミナルにゴミ箱の考え方を持ち込む [gomi](https://github.com/babarot/gomi) という CLI コマンドを作った。久しぶりに土日を使って、その UI を書き換えた。ファイルをゴミ箱に移したり戻したりするという根幹の機能は変えていない。

これまでは UI の実装に [promptui](https://github.com/manifoldco/promptui) を使っていた。ただ、Ctrl+W（単語の削除）が効かない、Ctrl+C で interrupt すると UI が崩れる、そもそも開発がしばらく止まっている、と気になるところがいくつかあった。そんなときに [bubbletea](https://github.com/charmbracelet/bubbletea)（Bubble Tea）[^tea] という UI ライブラリを知って、手間はかかりそうだったが、使ってみたい気持ちの方が大きかったので[置き換えることにした](https://github.com/babarot/gomi/pull/44)。

Bubble Tea は、設計に Elm Architecture（TEA: The Elm Architecture）を採用している。シンプルで管理しやすい UI を組むために、関数型プログラミングの考え方を取り入れたフロントエンドの設計パターンで、もともとは Elm という言語で使われていたもの。React や Redux の設計にも影響を与えているらしい。

## Elm Architecture とは

Elm Architecture は、主に以下の3つの要素で構成される。

| 要素   | 役割                                         |
|--------|----------------------------------------------|
| Model  | アプリのステート管理をする                   |
| Update | UI 操作や Message を受け取り、Model を更新する |
| View   | Model から UI を描画する                     |

Elm では View の戻り値として HTML を返すが、Bubble Tea では文字列を返す。実装する側は Model（ステート）を介して Update（処理）と View（見た目）を書くだけでよく、データの流れは Runtime に任せられる。View の処理が終わると、Runtime によってレンダリングされ、次のサイクルが動く。

<Partial name="elm-architecture" />

Bubble Tea では `Model` という interface で以下のメソッドを定義し、Elm Architecture を表現している。

- `Init()`: 初回の Message を送信し、サイクルをスタートさせる
- `Update()`: Message（キー入力などのイベント）を受け取り、適切な処理を行い、新しい Model を返す
- `View()`: 出力する文字列を組み立てて String を返す

`Model` interface を満たす構造体 `model` を作成し、`Update()` と `View()`、およびそれらを行き来する `Message` を実装していく流れになる。

キー入力やデータの変更など、いわゆるイベントは `Message` と呼ばれており、これを受け取った `Update` はそれに応じた処理を行い `View` を呼ぶ。`Quit`（サイクルの終了）処理などもユーザーが実装する部分なので、Bubble Tea は基本的に `Update ←(Model)→ View` をひたすら繰り返すというわけ。

Bubble Tea でターミナルアプリを書くのは今回が初めてだったが、状態と処理と見た目の置き場所が決まっているので、迷わずに書けた。最初に読んだ [@motemen さんのブログ](https://motemen.hatenablog.com/entry/2022/06/introduction-to-go-bubbletea)がとても参考になった。
